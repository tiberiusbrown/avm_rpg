# Tiled and 16x16 asset pipeline

Install `tools/requirements.txt`. Tiled is needed for visual map editing; XML and
Pillow suffice for regeneration. Run `python tools/generate_assets.py`, or use
`--check` to compare generated bytes. CMake tracks TMX, TSX and PNG inputs.

## Terrain and indices

Use finite orthogonal right-down TMX maps, 16x16 tiles, uncompressed CSV layers,
and external `assets/tilesets/world.tsx`. The maximum logical area remains
240x248 tiles. Storage chunks are 8x4 tiles (32 bytes). Layers flatten in document
order; zero GIDs leave underlying tiles untouched. Empty cells and padding become
the outside sentinel, 255. No flipping, rotation, infinite/compressed maps, offsets,
hidden/translucent layers or per-tile animation is supported.

`tiles16.png` is opaque monochrome, 256x256, with 16 columns and 16 rows. Runtime
ID equals `row * 16 + column`: the top-right cell is 0x0F, and the sign is 0x41.
The TSX declares all 256 cells, with `reserved=true` as the only property on cell
255. The exporter excludes that cell from runtime tiles and sprite frames; TMX
GID 256 with firstgid=1 is rejected. Usable cells have explicit `runtime_id`
0..254, unique `symbol`, and bool `solid`/`portal` properties. Blank black cells
remain valid indexed frames and are not deduplicated or removed. Unused cells
default to solid in this sample; mark new terrain deliberately when authoring.

Each 16x16 tile occupies 32 bytes: 16 top-page columns, then 16 bottom-page columns.
Within a byte, bit zero is the uppermost pixel. The sprite array begins with
width=16, height=16, followed by all 255 frames in runtime-ID order.

## Actors

`actors16.png` is 192x256 RGBA: 12 columns and 16 character rows. Every row has
three north, three east, three south and three west frames. Zero-based pose 0
is standing; walking uses offsets 0,1,0,2. Each pose lasts four simulation ticks.
`actor_frame()` shares this selection between player and NPC rendering. The
player uses row 0; `NpcDefinition::sprite_row` selects an NPC's row (0..15).

Opaque pixels must be black/white and alpha must be 0 or 255. Each actor frame
occupies 64 bytes: bitmap and mask bytes interleaved in page-major order. Alpha
alone defines opacity, so opaque black pixels erase underlying terrain while
transparent pixels preserve it. Each frame has its own mask. No standalone
`actor_mask.png` is used.

## Positions and native handlers

Each map declares unique byte `area_id`, C++ `symbol`, and `spawn` referencing
one named, passable, handler-free tile in that area. Spawns are sprite pixel
origins: tile (7,5) is pixel (112,80).

Use Logic/Locations object layers with no type/class. Point centers are
`(16*tx+8,16*ty+8)`; fractional points select their containing tile. Rectangles
cover every tile with positive-area overlap, with exclusive right/bottom edges.
The name is optional and must be a unique C++ identifier when supplied. The only
optional property is `handler`, naming a native function.

Named single tiles generate `positions::Name`; rectangles generate row-major
`positions::Name_0`, etc. Named rectangles additionally expose a `NameRegion`
query value. Unnamed handlers use private constexpr positions. Each covered
tile dispatches exactly once from its own 8x4 chunk. Moving a point across a
chunk boundary automatically relocates its generated call.

The exporter emits `Handler<POS, STAGE>` and empty defaults for every authored
handler name. Add ordinary overloads in `handler_impl`, after including
`handler_defaults.h`:

```cpp
template <TilePos POS> void read_sign(Dialogue<POS>) {
    if(player_just_interacted<POS>())
        dialogue_show(F("Welcome to Nocturne Grove."));
}
```

Overload `Gameplay<POS>`, `Tiles<POS>` or `Dialogue<POS>`. Finish the entire
gameplay pass, reload the baseline cache, finish all tile handlers, then run
dialogue. Generated dependent calls use ADL; do not qualify them. New named or
unnamed handlers compile with their empty defaults before behavior is written.
Blocking interactions belong to Dialogue. Runtime terrain reads stay cache-only.

`player_just_interacted<POS>()` advertises an A hint and consumes a fresh A edge
only while facing the adjacent foot-center tile. Held A and diagonal targets do
not interact. `player_is_walking_onto<POS>()` recognizes actual tile entry.
`teleport_player<TARGET>(facing=STILL)` uses 16-pixel tile origins and preserves
facing when STILL. It validates bounds and clears the NPC pool/input; destination
tiles are rebuilt before destination gameplay runs on the next frame.

Optional Routes layers contain named polylines, `mode=once/loop/reverse` and
integer `pause` 0..255. Points must lie inside tiles, not on their edges. Export
assigns route IDs by sorted name and stores two-byte tile coordinates in PROGMEM.
The sample clearing has no routes; native fixtures exercise the generic system.

## Build and verification

```powershell
python tools/generate_assets.py --check
./tools/build.ps1 -SdkRoot ../../build/avm-sdk-install
ctest --test-dir build -C RelWithDebInfo --output-on-failure
cmake --build build --config RelWithDebInfo --target rpg_integration
python tools/collect_evidence.py --build build --write-docs
```

`build.ps1` initializes the MSVC environment matching the configured compiler.
Keep RelWithDebInfo and guest full LTO. For native-only builds pass `-HostOnly`.
Full-device QA requires matching `AVM_SOURCE_ROOT` and `AVM_BUILD_ROOT`; SDK-only
builds still run LLDB guest probes and source profiles, with device QA explicitly
skipped. The default build refreshes root `rpg.arduboy`.
