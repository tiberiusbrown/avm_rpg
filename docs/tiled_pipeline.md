# Tiled and 16x16 asset pipeline

Install `tools/requirements.txt`. Tiled is needed for visual map editing; XML and
Pillow suffice for regeneration. Run `python tools/generate_assets.py`, or use
`--check` to compare generated bytes. CMake tracks TMX, TSX and PNG inputs. The
generator also writes `assets/images/<SYMBOL>_preview.png`, a 1x preview of each map with
every tile drawn from its atlas cell at 16x16 pixels; unpainted outside cells are gray.
For tile meanings and map design rules, see `assets/maps/AUTHORING.md`.

## Terrain and indices

Use finite orthogonal right-down TMX maps, 16x16 tiles, uncompressed CSV layers,
and one external tileset from `assets/tilesets`. The maximum logical area remains
240x248 tiles. Map data stores exactly width * height tile IDs in row-major order,
without chunk padding. The 8x4 chunks organize handler dispatch only.
Layers flatten in document order; zero GIDs leave underlying tiles untouched.
Empty cells become the outside sentinel, 255. No flipping, rotation, infinite/compressed maps, offsets,
hidden/translucent layers or per-tile animation is supported.

**Each map uses exactly one tileset, and the game selects the tileset by area.** A map
with two tileset references is rejected. Outdoor maps use `world.tsx` with
`tiles16.png`. `interiors.tmx` uses `house.tsx` with `tiles16_house.png`. `cave.tsx` and
`dungeon.tsx` have no map yet. The TSX `name` attribute names the tileset in generated
code and must be a lower-case identifier.

Every atlas is opaque monochrome, 256x256, with 16 columns and 16 rows. Runtime
ID equals `row * 16 + column` within its tileset: in the world tileset the top-right
cell is 0x0F and the sign is 0x41. A TSX declares all 256 cells, with `reserved=true` as
the only property on cell 255. The exporter excludes that cell from runtime tiles and
sprite frames; TMX GID 256 with firstgid=1 is rejected. Usable cells have explicit
`runtime_id` 0..254, unique `symbol`, an int `collision` mask from 0 to 65535, and a bool
`portal` property. `assets/maps/AUTHORING.md` describes the mask. Blank black cells
remain valid indexed frames and are not deduplicated or removed. Unused cells
default to full collision (65535); mark new terrain deliberately when authoring.

Tilesets in use get runtime indices: `world` is 0, and the others follow by name. The
generator emits:

- `area_ids.h`: `TILESET_<NAME>` indices, `TILESET_COUNT` and
  `constexpr uint8_t area_tileset(uint8_t area)`, a switch over the areas.
- `tile_ids.h`: `TILE_<symbol>` for the world tileset and `<NAME>_TILE_<symbol>` for each
  other tileset, such as `HOUSE_TILE_FLOOR_WOOD_A`.
- `map_assets.cpp`: `TILE_COLLISION`, one 256-entry block per tileset, read at
  `(area_tileset(game.area) << 8) | tile`. Entry 255 of each block is the solid sentinel.
- `sprites.cpp`: `TILE_SPRITES` and one `<NAME>_TILE_SPRITES` sheet per other tileset,
  with `tileset_sprites(tileset)` to select one. `rpg_render_world` draws with the sheet
  of the active area.

Only tilesets that a map references are emitted. The generator still parses every TSX in
`assets/tilesets` and writes `assets/images/<atlas>_collision.png` for each one, so an
unused tileset stays valid.

Each 16x16 tile occupies 32 bytes: 16 top-page columns, then 16 bottom-page columns.
Within a byte, bit zero is the uppermost pixel. Each tileset's sprite array begins with
width=16, height=16, followed by all 255 frames in runtime-ID order.

## Actors

`actors16.png` is 192x512 RGBA: 12 columns and 32 character rows. Every row has
three north, three east, three south and three west frames. Zero-based pose 0
is standing; walking uses offsets 0,1,0,2. Each pose lasts eight simulation ticks.
`actor_frame()` shares this selection between player and NPC rendering. The
player uses row 0; `NpcDefinition::sprite_row` selects an NPC's row (0..31).

Rows 0-15 are people. Rows 16-31 are creatures and enemies:

| Row | Character | Row | Character |
| --- | --- | --- | --- |
| 16 | Giant rat | 24 | Zombie |
| 17 | Wolf | 25 | Ogre |
| 18 | Giant bat | 26 | Goblin |
| 19 | Giant spider | 27 | Ghost |
| 20 | Giant beetle | 28 | Mushroom creature |
| 21 | Snake | 29 | Floating eye |
| 22 | Slime | 30 | Golem |
| 23 | Skeleton | 31 | Hooded cultist |

Creatures follow the same frame layout. West frames mirror the east frames, and a
character keeps the same head and body proportions in all four directions. Creatures
that do not step animate their two walking poses another way: the slime squashes and
stretches, the bat flaps, and the ghost and floating eye bob.

The sheet's height sets the row count: append whole 16-pixel rows to add characters,
then update `ACTOR_ROW_COUNT` in `src/rpg.h`. The generated `sprites.cpp` asserts that
the two agree.

Opaque pixels must be black/white and alpha must be 0 or 255. Each actor frame
occupies 64 bytes: bitmap and mask bytes interleaved in page-major order. Alpha
alone defines opacity, so opaque black pixels erase underlying terrain while
transparent pixels preserve it. Each frame has its own mask. No standalone
`actor_mask.png` is used.

## Positions and native handlers

Each map declares unique byte `area_id`, C++ `symbol`, and `spawn` referencing
one named, passable, handler-free tile in that area. Spawns are sprite pixel
origins: tile (7,5) is pixel (112,80).

Use Logic/Locations object layers with no type/class. Point centers are
`(16*tx+8,16*ty+8)`; fractional points select their containing tile. Rectangles
cover every tile with positive-area overlap, with exclusive right/bottom edges.
The name is optional and must be a unique C++ identifier when supplied. The only
optional property is `handler`, naming a native function.

Named single tiles generate `positions::Name`; rectangles generate row-major
`positions::Name_0`, etc. Named rectangles additionally expose a `NameRegion`
query value. Unnamed handlers use private constexpr positions. Each covered
tile dispatches exactly once from its own 8x4 chunk. Moving a point across a
chunk boundary automatically relocates its generated call.

The exporter emits `Handler<POS, STAGE>` and empty defaults for every authored
handler name. Add ordinary overloads in `handler_impl`, after including
`handler_defaults.h`:

```cpp
template <TilePos POS> void read_sign(Dialogue<POS>) {
    if(player_just_interacted<POS>())
        dialogue_show(F("Welcome to Nocturne Grove."));
}
```

Overload `Gameplay<POS>`, `Tiles<POS>` or `Dialogue<POS>`. Finish the entire
gameplay pass, reload the baseline cache, finish all tile handlers, then run
dialogue. Generated dependent calls use ADL; do not qualify them. New named or
unnamed handlers compile with their empty defaults before behavior is written.
Blocking interactions belong to Dialogue. Runtime terrain reads stay cache-only.

`player_just_interacted<POS>()` advertises an A hint and consumes a fresh A edge
only while facing the adjacent foot-center tile. Held A and diagonal targets do
not interact. `player_is_walking_onto<POS>()` recognizes actual tile entry.
`teleport_player<TARGET>(facing=STILL)` uses 16-pixel tile origins and preserves
facing when STILL. It validates bounds and clears the NPC pool/input; destination
tiles are rebuilt before destination gameplay runs on the next frame.

Optional Routes layers contain named polylines, `mode=once/loop/reverse` and
integer `pause` 0..255. Points must lie inside tiles, not on their edges. Export
assigns route IDs by sorted name and stores two-byte tile coordinates in PROGMEM.
The outdoor map has no routes; native fixtures exercise the generic system.

## Build and verification

```powershell
python tools/generate_assets.py --check
./tools/build.ps1 -SdkRoot ../../build/avm-sdk-install
ctest --test-dir build -C RelWithDebInfo --output-on-failure
cmake --build build --config RelWithDebInfo --target rpg_integration
python tools/collect_evidence.py --build build --write-docs
```

`build.ps1` initializes the MSVC environment matching the configured compiler.
Keep RelWithDebInfo and guest full LTO. For native-only builds pass `-HostOnly`.
Full-device QA requires matching `AVM_SOURCE_ROOT` and `AVM_BUILD_ROOT`; SDK-only
builds still run LLDB guest probes and source profiles, with device QA explicitly
skipped. The default build refreshes root `rpg.arduboy` and builds the marker-bearing
`build/artifacts/rpg_qa.arduboy` that device QA reads.
